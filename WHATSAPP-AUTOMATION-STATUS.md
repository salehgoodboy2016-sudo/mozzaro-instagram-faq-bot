# Mozzaro WhatsApp automation — prepared, disabled

The production WhatsApp phone `+966565017314` must remain in the WhatsApp Business mobile app. This repository does not call `/register`, migrate the number, or start Embedded Signup. WhatsApp replies default to OFF; Instagram keeps its independent configuration and routes.

## Implemented in code

- Separate WhatsApp FAQ rules for approved Arabic answers, Riyadh opening hours, complaints, multiple questions, and a human-review fallback. No AI API is currently used and no restaurant fact is generated by a model.
- WhatsApp GET challenge verification and signed POST validation with raw-body HMAC. Valid events are acknowledged; invalid signatures or JSON are rejected. Logs contain only aggregate outcomes and error codes.
- PostgreSQL-backed incoming event deduplication and conversation handoff. A verified `smb_message_echoes` event marks a conversation for human handling. `history` and `smb_app_state_sync` are accepted without importing private history or contacts; full synchronization is pending Coexistence.
- Cloud API text transport with a 24-hour customer-service-window check, disabled by default. Ambiguous send failures are marked for review and never retried automatically. Mock transport is used in tests.
- Token-protected internal endpoints: `GET /admin/whatsapp/status`, `POST /admin/whatsapp/preview` (body `{ "text": "..." }`), and `POST /admin/whatsapp/handoff` (body `{ "conversationId": "<64 hex>", "active": true|false }`). Supply `Authorization: Bearer <MOZZARO_ADMIN_API_TOKEN>`. No endpoint turns on live automation.
- Dormant Embedded Signup v4 helpers in `src/coexistence-signup.mjs` for the special `whatsapp_business_app_onboarding` feature and secure completion validation. There is deliberately no live launch route.

## Configuration

Keep `WHATSAPP_AUTO_REPLY_ENABLED=false`, `WHATSAPP_COEXISTENCE_VERIFIED=false`, `WHATSAPP_EMPLOYEE_ECHO_VERIFIED=false`, and `WHATSAPP_LIVE_SEND_APPROVED=false` on Render. The webhook's existing `WHATSAPP_WEBHOOK_VERIFY_TOKEN` and `WHATSAPP_WEBHOOK_APP_SECRET` remain separate from Instagram settings. `WHATSAPP_ACCESS_TOKEN` is not currently configured on Render and is not required while outbound is disabled.

Before a future, separately approved activation, provide a durable `WHATSAPP_DATABASE_URL` (PostgreSQL), a random `WHATSAPP_IDENTITY_KEY` for one-way conversation identifiers, a fresh `WHATSAPP_ACCESS_TOKEN`, and `MOZZARO_ADMIN_API_TOKEN`. Do not put values in Git or chat. The free Render container filesystem cannot reliably store idempotency state across deployments. Obtain permission and verify the live phone and echo webhook before changing the four disabled flags.

The tracked migration runner is `pnpm db:migrate`; startup runs the same
idempotent migrations under a PostgreSQL advisory lock. See
`WHATSAPP-DATABASE.md` for the exact Render requirements. Render's free
PostgreSQL plan currently expires after 30 days, so it is suitable only for a
connection rehearsal and is not durable production storage.
